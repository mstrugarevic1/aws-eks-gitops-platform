# Contributing

## Before opening a pull request

```bash
make check
```

That runs the local subset of CI: Terraform formatting, JSON parsing, GitOps
rendering and its determinism check, unit tests, shellcheck, and Helm lint and
template for every environment. It needs no AWS credentials and touches no
cluster.

## Rules that CI enforces

- **Rendered GitOps manifests are committed.** `gitops/environments/*/apps/`,
  `root-app.yaml`, `values/` and `manifests/` are generated by
  `scripts/gitops.py`. Change the input (`gitops/base/components.json` or an
  `environment.json`), run `make gitops-render ENV=<env>`, and commit both.
- **Environments come from `gitops/environments/environments.json`.** Do not
  hardcode environment names in Makefile targets, scripts or workflows.
- **Chart versions are pinned.** Every entry in `components.json` needs an
  explicit `targetRevision`. The ArgoCD chart is pinned in the Makefile.
- **Image tags are explicit.** `latest` is rejected by validation, and ECR
  repositories are created with immutable tags.
- **No credentials.** Gitleaks runs on every pull request.

## Adding a component

1. Add it to `gitops/base/components.json` with a pinned version and a sync wave.
2. Add its enable flag to every `environment.json`.
3. Render and validate: `make gitops-render ENV=dev`.
4. Commit the inputs and the rendered output together.

See [docs/configuration.md](docs/configuration.md) for the environment values
that feed Terraform and GitOps.

## Commit messages

Short, imperative, prefixed by area: `feat:`, `fix:`, `docs:`, `chore:`.

## Recommended GitHub settings

These live outside the repository and have to be set in the GitHub UI.

Repository:

- Name: `eks-gitops-platform`
- Description: `Reusable AWS EKS platform built with Terraform, ArgoCD App of Apps, Helm and GitOps.`
- Topics: `aws`, `eks`, `terraform`, `kubernetes`, `argocd`, `gitops`, `helm`,
  `platform-engineering`, `external-secrets`, `victoriametrics`

Branch protection on `main`:

- require a pull request before merging
- require the `Checks` workflow to pass
- require branches to be up to date before merging
- block force pushes and branch deletion

Other:

- enable automatic deletion of merged branches
- enable Dependabot alerts and security updates (`.github/dependabot.yml` covers
  GitHub Actions, Terraform, Docker and pip)
- enable secret scanning and push protection
- set default GitHub Actions permissions to read-only; the workflows here grant
  write scopes per job, and only where needed
