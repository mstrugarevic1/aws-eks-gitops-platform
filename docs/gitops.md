# GitOps layout

## What is generated and what is written by hand

Written by hand:

```text
gitops/base/components.json          component registry: what exists, which chart, which version
gitops/environments/environments.json list of environments
gitops/environments/<env>/environment.json  per-environment configuration
gitops/apps/example-app/chart/       the application chart and its per-env values
```

Generated by `scripts/gitops.py render <env>` and committed:

```text
gitops/environments/<env>/root-app.yaml   the App of Apps root Application
gitops/environments/<env>/apps/*.yaml     one child Application per enabled component
gitops/environments/<env>/values/*.yaml   IRSA annotations and other rendered Helm values
gitops/environments/<env>/manifests/      ClusterSecretStore and ExternalSecret
```

Never edit a generated file: the next render overwrites it, and CI fails if the
committed output does not match what the renderer produces.

## components.json

Each entry describes one ArgoCD Application:

| Field | Meaning |
| ----- | ------- |
| `name` | component name; the Application is `<env>-<name>` |
| `enabledKey` | dotted path in `environment.json` that turns it on or off |
| `wave` | ArgoCD sync wave; lower runs first |
| `namespaceKey` | key under `namespaces` in `environment.json` |
| `createNamespace` | adds `CreateNamespace=true` to the sync options |
| `valueFiles` | Helm values files, relative to the environment or the repository |
| `valueFilesFromEnv` | Helm values file names read from `environment.json` |
| `helmParametersFromEnv` | individual Helm `--set` values read from `environment.json` |
| `source.chart` / `source.repoURL` / `source.targetRevision` | a Helm chart from a remote repository |
| `source.path` | a directory in this repository |
| `source.include` | file glob when only part of a directory should be applied |

`targetRevision` is required for chart sources and must be an explicit version.

## environment.json

```json
{
  "name": "dev",
  "repoURL": "git@github.com:mstrugarevic1/eks-gitops-platform.git",
  "targetRevision": "main",
  "aws": { "accountId": "…", "region": "…", "clusterName": "…", "vpcId": "…", "roles": { … } },
  "namespaces": { "system": "kube-system", "app": "example-app", … },
  "addons": { "metricsServer": true, … },
  "apps": { "exampleApp": true },
  "exampleApp": {
    "valuesFile": "values-dev.yaml",
    "image": { "repository": "…", "tag": "0.1.0" },
    "secretName": "example-app",
    "secretManagerPath": "my-platform/dev/example-app"
  },
  "syncPolicy": { "automated": { "prune": true, "selfHeal": true } }
}
```

The `aws` block, `exampleApp.image.repository` and `exampleApp.secretManagerPath`
are filled by `make configure-gitops-values ENV=<env>` from Terraform outputs.
Committed files hold placeholders (`AWS_ACCOUNT_ID`, `VPC_ID`,
`ECR_REPOSITORY_URL`), and validation rejects them, so an unconfigured
environment cannot be synced by accident.

`production` keeps `automated.prune` disabled. Validation enforces that.

## Enabling and disabling components

```json
{
  "addons": {
    "storageclass": true,
    "metricsServer": true,
    "awsLoadBalancerController": true,
    "clusterAutoscaler": true,
    "externalSecrets": true,
    "observability": false
  },
  "apps": { "exampleApp": true }
}
```

Then:

```bash
make gitops-render ENV=dev
make gitops-validate ENV=dev
```

Disabling a component removes its Application file. With `prune` enabled ArgoCD
deletes the resources it created; in `production` they are left in place and must
be removed deliberately.

## Adding an application

1. Put the chart in `gitops/apps/my-app/chart/` with a `values-<env>.yaml` per
   environment.
2. Register it:

   ```json
   {
     "name": "my-app",
     "enabledKey": "apps.myApp",
     "wave": 20,
     "namespaceKey": "app",
     "createNamespace": true,
     "valueFilesFromEnv": ["myApp.valuesFile"],
     "helmParametersFromEnv": [
       { "name": "image.repository", "valueRef": "myApp.image.repository" },
       { "name": "image.tag", "valueRef": "myApp.image.tag" }
     ],
     "source": { "path": "gitops/apps/my-app/chart" }
   }
   ```

3. Add `apps.myApp` and a `myApp` block to every `environment.json`.
4. `make gitops-render ENV=<env>` and commit the inputs with the output.

## Image tags

Image repository and tag are Helm parameters taken from `environment.json`, not
values in the chart. Promoting a build is a one-line change to that file:

```bash
make build-app ENV=dev TAG=0.2.0
make set-image-tag ENV=dev TAG=0.2.0
git add gitops/ && git commit -m "chore: dev to 0.2.0" && git push
```

`latest` is rejected by validation. ECR repositories are created with immutable
tags, so a moving tag could not be re-pushed anyway, and ArgoCD would not be able
to tell one rollout from the next.

## Repository access

ArgoCD pulls from the remote Git repository. How it authenticates depends on the
repository:

| Repository | Approach |
| ---------- | -------- |
| Public, HTTPS `repoURL` | no credential needed; skip the rest of this section |
| Private | SSH deploy key (recommended here) or a GitHub App |

A GitHub App is the better long-term answer for an organisation: short-lived
tokens, per-repository scope, no key to rotate by hand. A deploy key is used here
because it takes one command and no GitHub org configuration.

An HTTPS personal access token works for a quick local demonstration, but it is
tied to a person, usually broader than one repository, and long-lived. Do not use
one for anything that outlives the demo.

### SSH deploy key

Generate a key that exists only on your machine and in GitHub:

```bash
ssh-keygen -t ed25519 -N "" -C "argocd-dev" -f ~/.ssh/argocd_deploy_key
```

Add the **public** half in GitHub under *Settings → Deploy keys → Add deploy
key*. Leave *Allow write access* unchecked: ArgoCD only reads.

Register the **private** half with ArgoCD:

```bash
make configure-argocd-repository ENV=dev SSH_KEY_FILE=~/.ssh/argocd_deploy_key
```

That creates a labelled `repository` Secret in the `argocd` namespace. The key
file stays where it is; nothing is written into the repository, and
`argocd-repo-key*` is gitignored.

`repoURL` in `environment.json` must be the SSH form
(`git@github.com:owner/repo.git`) and must match the URL in the Secret exactly.
ArgoCD matches credentials by URL string.

### Verifying connectivity

```bash
kubectl -n argocd get secret -l argocd.argoproj.io/secret-type=repository
argocd repo list
```

`argocd repo list` should show the repository with status `Successful`. Without
the CLI:

```bash
kubectl -n argocd logs deploy/argocd-repo-server --tail=50
```

Authentication failures appear there as `permission denied (publickey)` or
`could not read Username`.
